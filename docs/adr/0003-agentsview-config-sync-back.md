# ADR-0003: AgentsView config.toml — version-controlled copy with git-review sync-back

- **Status**: Accepted
- **Date**: 2026-09-19
- **Deciders**: Matthias (config owner), coding agent

## Context

[AgentsView](https://github.com/kenn-io/agentsview) (local web viewer for AI
coding-agent sessions) is installed via the Nix module
`modules/agentsview.nix` (ADR-scope: release binary + declarative
`~/.agentsview/config.toml` generated by `pkgs.formats.toml`; no Docker, no
Homebrew). Its single-binary design means the daemon, the web UI, and the CLI
all share one config file — and **more than one writer**:

| # | Occasion | Typical keys touched |
|---|----------|----------------------|
| 1 | First run — file auto-created | (file created) |
| 2 | Secret generation | `cursor_secret` (HMAC key, always written when missing), `auth_token` (written when `require_auth` is on and no token exists) |
| 3 | Web UI **Settings** page | `archive_content`, `tool_result_images` (Settings > Archive content), `chart_palette`, `zoom_level` (Settings > Appearance), `disabled_agents` + `agents.<id>.homes` (Session Providers), remote-access fields (`host`, `public_url`, `public_origins`) |
| 4 | Gist publishing | `github_token` (Settings page or `POST /api/v1/config/github`) |
| 5 | Legacy-format conversion on startup | rewrites the whole file (formatting, comments, key layout) |

Home Manager currently *owns* the file: every `darwin-rebuild switch`
overwrites `~/.agentsview/config.toml` with the Nix-generated version and
discards anything the daemon wrote since the last switch (the Home-Manager
backup `config.toml.bak` is the only remnant, and it is silently rotated).

Some of the daemon-written state is **vital to preserve**: an auto-generated
`auth_token` under `require_auth = true` is the only way to reach the API;
UI-configured `disabled_agents` / palette / zoom are real user intent.

Requirement: daemon-written changes must survive a rebuild, and the flow must
remain declarative, reviewable and simple. Explicit non-goals from the
outset: no Docker, no Homebrew, no tooling that silently rewrites the Nix
configuration behind the user's back.

## Decision

**The config file's source of truth is a version-controlled TOML file in the
repo, synced back by copying, with a human git diff as the merge arbiter —
not an automated merge.**

Concretely:

1. **Source of truth moves into VCS**: the module installs
   `config/agentsview/config.toml` (repo) verbatim to
   `~/.agentsview/config.toml`. The generated-from-Nix-options path is kept
   as a fallback (`configFile` option: `nullOr path`, default
   `../config/agentsview/config.toml`; `null` ⇒ generate from
   `programs.agentsview.settings` as before).
2. **Sync back is a plain copy, reviewed as a git diff**:
   `make sync-config-agentsview` copies the live `~/.agentsview/config.toml`
   over `config/agentsview/config.toml` (redacting secret keys, see below),
   shows the `git diff`, and exits. The user then either
   **approves** (commit — the change becomes declarative truth) or
   **rejects** (`git checkout -- config/agentsview/config.toml` — the change
   stays runtime-only and *will* be lost on the next switch, which is exactly
   the semantics the review is for).
3. **Secrets never enter VCS**: `cursor_secret`, `auth_token`, `github_token`
   are redacted by `sync-config-agentsview` on copy. They are migrated to the
   repo's encrypted-secret stack via `make import-secrets-agentsview` (see
   below), exposed to the daemon as environment variables
   (`AGENTSVIEW_AUTH_TOKEN`, `AGENTSVIEW_GITHUB_TOKEN`) which **override**
   the config file — so the daemon stops writing secret keys into
   `config.toml` at all, and the diff stays reviewable.
4. **No automated merge**: no TOML diffing, no key-level three-way merge, no
   activation-time splicing. Git + human review is the merge.

### Why not a "perfect merge"

An automated sync-back (parse live TOML, diff against the Nix baseline,
disambiguate "UI change" vs "stale file vs. Nix edit", emit a runtime
override module) was designed and discarded: it needs a baseline file,
per-key change-intent heuristics and a second shadowing source of truth
that shadows future Nix edits. The copy-and-review flow needs ~50 lines of
shell, has no heuristics, and every conflict resolution is an explicit,
reviewable git decision. Same philosophy as ADR-0001: reconciling
imperative tool behavior is fine as long as the resulting state is explicit
in the flake.

## Workflow

```text
Normal use:
  UI change  →  make sync-config-agentsview
            →  review `git diff config/agentsview/config.toml`
            →  approve: git add + commit        |  reject: git checkout --
            →  make build (optional diff) → make switch
            →  agentsview daemon restart  (picks up the new file)

Secrets (once, or when rotating):
  make import-secrets-agentsview
    → extracts cursor_secret/auth_token/github_token from the live config
    → sops-encrypts into secrets/agentsview.yaml
    → module maps them to AGENTSVIEW_AUTH_TOKEN / AGENTSVIEW_GITHUB_TOKEN
      (cursor_secret is intentionally NOT persisted, see Consequences)
```

| Makefile target | Effect |
|---|---|
| `sync-config-agentsview` | live config → `config/agentsview/config.toml` (secrets redacted), prints `git diff`, exit code 0 both when diff empty and when changes await review |
| `import-secrets-agentsview` | live config secrets → `secrets/agentsview.age` (agenix-encrypted), interactive editor flow; refuses to write plaintext |
| (unchanged) `switch` / `setup` | applies the module; `~/.agentsview/config.toml` becomes the VCS copy |

### Secret mechanism

> **Superseded 2026-09-19 by ADR-0004**: the secret stack is **agenix**;
> the dormant sops-nix scaffold is removed. The original sops-based sketch
> is kept below for history; `import-secrets-agentsview` is implemented as
> `agenix -e secrets/agentsview.age` instead of a sops YAML writer.

The repo ships **sops-nix** (age-backed) — but note it is *wired, not in
use*: `home/secretmanagement.nix` loads `inputs.sops-nix.homeManagerModules
.sops` and an age keypair exists (`key.txt`, gitignored; its public key
matches the recipient in `secrets/test.yaml`), yet no `sops.secrets` are
declared anywhere and no repo-root `.sops.yaml` exists. Adopting this ADR
therefore means standing up the first real sops usage:

- create `.sops.yaml` with `age1l5kln63qmzn9chkp6ehee4p33y3j6e5a8znsz23g0yq0r
  20zwd9sehqn0k` as creation rule
- `secrets/agentsview.yaml` encrypted with `SOPS_AGE_KEY_FILE=./key.txt sops …`

The ADR nominally calls for *agenix*; the decision is **sops-nix instead** —
functionally equivalent (encrypted file in VCS, decrypted to a target path
at activation) and it avoids running two parallel secret stacks.
Implementation sketch:

```nix
# secretmanagement.nix / agentic.nix
sops.secrets."agentsview/auth_token" = {
  sopsFile = ../secrets/agentsview.yaml;
  path = ".agentsview/secrets/auth_token";   # mode 0600
};
home.sessionVariables = {
  # imported from the decrypted file at activation, or read via sops templates
  AGENTSVIEW_AUTH_TOKEN = "...";
};
```

Environment wins over the config file for both keys (upstream-documented
precedence), so the daemon reads the secret from the environment and no
longer embeds it in `config.toml`.

## Architecture (files touched by implementation)

- `config/agentsview/config.toml` — version-controlled source of truth
- `modules/agentsview.nix` — `configFile` option (path | null → generated)
- `Makefile` — `sync-config-agentsview`, `import-secrets-agentsview`
- `scripts/sync-config-agentsview.sh` — copy + redact (`cursor_secret`,
  `auth_token`, `github_token` lines) + `git --no-pager diff` + non-zero
  reminder when uncommitted
- `secrets/agentsview.yaml` — sops file (age recipient already in the repo)
- `home/agentic.nix` — wires sops secrets to env vars

## Consequences

### Positive

- One source of truth (a TOML file a human can read and diff), reviewed
  through the same git flow as every other dotfile.
- No hidden machinery: what the diff shows is exactly what switches in.
- Secrets handled by the existing sops-nix stack; VCS stays clean.
- The daemon can keep rewriting its file freely between switches; nothing
  fights at runtime.

### Negative

- **Manual step**: forgetting `make sync-config-agentsview` before switching
  discards UI changes (mitigation: the Makefile `switch`/`setup` targets can
  run the sync first and print the diff so the loss is at least visible).
- Review quality is on the user: the diff can be large (upstream rewrites
  TOML formatting/comments on legacy conversion), and rejecting a diff
  discards real UI work that must be redone.
- `sync-config-agentsview` overwrites the VCS file wholesale — concurrent
  hand-edits to the VCS file since the last commit must be preserved by the
  user before syncing (git will surface them as part of the diff, but
  wholesale overwrite can mix intents; acceptable for a single-machine
  dotfiles repo).

### Risks

- Secret leakage into git: mitigated by redaction in the script *and* by the
  env-var precedence making the daemon not write the keys anymore. A CI /
  pre-commit grep for `cursor_secret =|auth_token =|github_token =` against
  `config/` is a cheap additional guard.
- `cursor_secret` regenerates on every switch (it is not exported via env
  var). Impact is deliberately accepted: it only signs pagination cursors,
  so old page links break — cosmetic. If upstream ever adds
  `AGENTSVIEW_CURSOR_SECRET`, move it to sops too.
- Keys written by the daemon that the redaction list doesn't know about
  (future upstream additions) land in VCS plaintext until noticed — same
  guard covers them.

## Alternatives considered (and rejected)

| Alternative | Reason rejected |
|---|---|
| Activation-time merge (HM activation hook merges daemon-managed keys from the `.bak` backup into the generated file) | Fights Home Manager's file model (symlink to read-only store), hides which file is authoritative, and the merged result silently diverges from the flake |
| Automated drift-diff sync-back (parse both files, emit runtime-override JSON/Nix, disambiguate UI-change vs. Nix-edit via previous snapshot) | Correct but ~heuristic; two sources of truth that shadow each other; the failure mode ("why didn't my Nix edit apply?") is exactly the class of bug ADR-0002 was written to end |
| Env-var-only (all daemon-writable keys via `AGENTSVIEW_*` env vars) | Impossible: Settings-page keys (`chart_palette`, `zoom_level`, `disabled_agents`, `agents.<id>.homes`) have no env overrides; only secrets do |
| Leave `config.toml` unmanaged by Nix (first run only) | Loses the "declarative and reproducible" contract this repo exists for; upgrades/rotations untracked |
| `home-manager.backupFileExtension` alone (`config.toml.bak`) | Already in place, but a `.bak` file is not a reviewable, versioned source of truth and rots unnoticed |
